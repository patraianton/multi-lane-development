# Пилот «без доски»: как ведём спринт с 15.09.2026

Простой документ для сессии CTO, которая запускает спринт по новому процессу. Он заменяет на время
пилота цепочку доски (проверка по спеке → ревью → починки → QA-раунды). Доска на паузе. Решение Антона
15.09.2026: «мы не NASA, у нас простой агрегатор».

## 1. Зачем

Старая цепочка чинила следствие: полоса писала «сделано», а требования были пропущены. В ответ появлялись
новые проверяльщики, круги и потолки. Итог по замерам 10–15.09: на один PR до 13 прогонов Codex на `ultra`
с пятью помощниками, 26 кругов и 18 часов на большом PR, а CI на критическом пути — 5 % времени. Каждый
проверяльщик — новый агент без памяти, и каждый круг приносит новые замечания на старый код.

Новый принцип: **доказывает тот, кто делал; проверяет один и с памятью; человек смотрит картинки.**

## 2. Что убираем, что оставляем

Убираем на время пилота: агентов по спеке (S-круги), агентов-ревьюеров (R-круги), круги починок больше
одного, потолки, ожидание квитанций стейджинга, QA-раунды с нарезкой тикетов и сворачиванием, `ultra` и
помощников на полосах, полную локальную проверку перед каждым пушем.

Оставляем без изменений: один тикет на спеку; короткий `pr-ci` на каждый пуш и полный по метке `full-ci`
перед вливанием; вливание только на зелёный `pr-ci-full` точной головы; независимая приёмка для защищённых
областей (миграции и схема, вход, выкат и кэш, сборщик); автовыкат .lv с main; Amp QA-орб после выката;
режим бэкапов базы; никаких сборок на Windows Антона.

## 3. Роли

| Кто | Что делает |
|---|---|
| Антон | Даёт спеку. Смотрит скриншоты и бой две минуты. Слово нужно только для денег, исходящего, стратегии. |
| Окно CTO (Claude, Fable) | Режет спеку в один тикет, запускает полосу, читает вердикт, разруливает споры, ставит `full-ci`, вливает. Пока идёт спринт — держит себя в цикле, не заканчивает. |
| Полоса (Codex на Mac) | Пишет код, сама доказывает каждое требование, открывает PR, пишет DONE с таблицей. |
| Проверяющий (Amp-орб, стоячий тред) | Просыпается по DONE, один проход, один вердикт комментарием. Не больше 30 минут. |
| CI | `pr-ci` короткий на пуш, полный по метке. Сетка от регрессий. |
| Amp QA-орб | После выката ходит по бою, заводит тикеты `[prod-qa]`. Уже работает (`prod-qa-amp.yml`). |
| Женя | Приёмка по тем же скриншотам и таблице. Вернул — один тикет-починка, без нового раунда. |

## 4. Процесс по шагам

**Шаг 0. Подготовка (один раз, ~2 часа, до первого тикета).**
- Навык проверяющего `.agents/skills/pr-review/SKILL.md` в репозитории продукта: что читать, как выглядит
  вердикт, запрет второго NO-GO.
- Воркфлоу `pr-review-amp.yml`: на комментарий `DONE` (или метку `review`) будит стоячий тред Amp
  (`amp threads continue $AMP_REVIEW_THREAD_ID -ox "Review PR #N"`), таймаут 30 минут. Секрет `AMP_API_KEY`
  и переменная треда уже есть по образцу `prod-qa-amp.yml`.
- Скрипт-сторож таблицы: пустая колонка «чем доказано» → орб не просыпается, полосе пишется одна строка.
- Проверяющему нужны два доступа, иначе он пишет «не ходится»: логин/пароль стейджинга в сообщении пробуждения
  (секрет репо) и доступ приложения Amp к `autopase-evidence` (клик владельца организации в настройках GitHub).
  Пока доступа к evidence нет — окно CTO зеркалит спек и скриншоты в ветку `artifacts/<тикет>` (папка
  `artifacts/task-<тикет>/`), и полоса обновляет зеркало перед каждым DONE.
- Доска на паузу: задача `mld-board` на Windows Антона выключена на время пилота.
- В `maclane`/запуске полосы по умолчанию `-m gpt-5.6-sol -c model_reasoning_effort=xhigh`, помощников 1
  (`agents.max_concurrent_threads_per_session=1`; 0 Codex не принимает). Никакого `ultra`. `gpt-6-astra` — не по
  умолчанию и не по старой памяти, а отдельное решение окна CTO на конкретный большой тикет при проверенной квоте
  (Astra сжигает недельную квоту в разы быстрее: 07.09 и 15.09 подписки вылетали). В тикете записать модель прогона —
  на пилоте меряем круги и часы по моделям: возможно, дороже на участке, но дешевле на дистанции (Антон, 15.09).

**Шаг 1. Тикет.** Окно CTO делает из спеки ОДИН тикет в GitHub (правило от 04.09 остаётся). В тикете —
таблица требований из спеки с пустой колонкой «чем доказано». 15 минут.

**Шаг 2. Запуск полосы.** Окно CTO пишет `~/kitchens/autopase.lv/TASK-<тикет>.md` по шаблону из раздела 5
и запускает одной командой (`mac autopase.lv "Прочитай ~/kitchens/autopase.lv/TASK-<тикет>.md и выполни
целиком"`). Полоса не ждёт CI и не ждёт ревью.

**Шаг 3. PR.** Полоса открывает PR, `pr-ci` короткий идёт сам (~12 мин). Полоса пишет комментарий `DONE`
с заполненной таблицей и ссылками на скриншоты в `Baltic-OrangesLV/autopase-evidence`.

**Шаг 4. Проверка.** Воркфлоу будит Amp-проверяющего. Один проход: таблица против спеки, скриншоты
рядом с макетами, дифф, стейджинг головы (если собран). Один комментарий: `GO` или `NO-GO` со списком
не длиннее десяти строк. Что не ломает поведение и не пропускает требование — в список «доводка», не блокер.

**Шаг 5. Починка (максимум одна).** `NO-GO` → окно CTO читает. Согласно — одна команда полосе «почини
список из вердикта», шаги 3–4 повторяются один раз. Второй `NO-GO` — решает окно CTO (чинит само,
вливает с оговоркой или несёт Антону). Третьего круга нет.

**Шаг 6. Вливание.** `GO` → окно CTO ставит `full-ci`, ждёт зелёный `pr-ci-full` на точной голове,
вливает. Выкат .lv идёт сам. Для защищённых областей — перед вливанием независимая приёмка, как сейчас.

**Шаг 7. Взгляд человека.** Антон или Женя смотрят скриншоты из PR и бой. Находки → один тикет-починка,
он идёт по шагам 2–6. Amp QA-орб после выката заводит свои тикеты, они идут так же.

## 5. Шаблон задания для полосы (TASK-<тикет>.md)

```
# Тикет #<номер> — <название>

Спека: <путь или ссылка>. Ветка: feat/<номер>. Репозиторий: Baltic-OrangesLV/vincheck-latvia.

Сделать всё, что в спеке. Три рынка — одна правка (CLAUDE.md).

Перед КАЖДЫМ пушем — только это, не больше:
  npx eslint <изменённые файлы>
  npx tsc --noEmit
  npx vitest run --changed origin/main
ОДИН раз перед DONE — полный `npx vitest run` (без сборки и без Playwright): в репозитории ~150 тестов-сторожей
читают исходники через readFileSync, и `--changed` их не выбирает (пилот №1: 12 таких падений всплыли только
на полном CI и стоили третьего прогона). Сборку и Playwright гоняет CI.

Запрещено: трогать миграции/схему, вход, выкат, сборщик без пометки «защищённая область» в PR;
удалять или пропускать тесты; ждать CI или ревью; работать дольше 6 часов подряд — остановись и напиши, где ты.

«Сделано» = ВСЁ ТРИ вместе:
  1. PR открыт, pr-ci короткий зелёный.
  2. В evidence-репо (~/kitchens/autopase.lv/evidence/<спринт>/<тикет>/) лежит скриншот КАЖДОЙ поверхности
     из спеки рядом с её макетом, 1440×900 и 390×844, запушено.
  3. Комментарий DONE в PR с таблицей ниже, без пустых строк.

| № | Требование из спеки (дословно, коротко) | Чем доказано (тест / скриншот / адрес) | Файл |
|---|---|---|---|
| 1 | ... | ... | ... |

Строка без доказательства = задача не сделана. Не пиши «сделано» словами — только таблица.
Последняя строка отчёта: DONE #<номер> <sha головы>.
```

## 6. Шаблон вердикта проверяющего

```
GO | NO-GO  head <sha>
Требования: <n> из <m> доказаны.
Блокеры (только поведение и пропущенные требования):
 1. §<раздел> — спека говорит … — код/скриншот показывает … — путь:строка
Доводка (не блокирует, в отдельный тикет после выката):
 - ...
Стейджинг: обошёл <адрес> | не собран | не ходится (ACCOUNT_AUTH=0 — кабинет)
```

## 7. Что меряем на пилоте

Сравниваем с 10–15.09 (данные в `_conveyor/autopase.lv/reports/ci-time-2026-09-15/`):

| Показатель | Было | Цель |
|---|---|---|
| Прогонов Codex на PR | до 13, с помощниками до 65 | 2 (полоса + одна починка) |
| Кругов на большом PR | 12–26 | ≤ 3 |
| Часов от тикета до вливания | 18–24 | ≤ 8 |
| Полных прогонов pr-ci на PR | ≈ 2 | 1 |
| Возвраты Жени | «в большинстве случаев» | считаем штуки |

**Пилот №1 — тикет #2334 (карточка v12, 36 требований), 15.09.2026:** прогонов Codex на PR — 3 (работа, починка по
вердикту, починка тестов-сторожей после полного CI) плюс один прерванный старт; проверок — 2 (оба NO-GO: первый —
Nord выключен, пустой тест действий, evidence недоступен; второй — 28/36, остаток ушёл в доводку #2344); кругов — 3
плюс правка CSS окном CTO; от тикета до вливания — 6 ч 38 мин; полных прогонов pr-ci — 2 (первый красный по
сторожам). Возвраты Жени — считать после его взгляда.

Если Женя вернул — сначала смотрим, что именно пропущено и почему таблица это не поймала. Чиним
постановку или шаблон, а не добавляем проверяльщика.

## 8. Чего не делать

- Не запускать панели агентов для проверки. Проверяющий один.
- Не заводить тикет на каждую находку. Одна починка — один тикет.
- Не ставить `full-ci` до `GO`: метка на открытом PR делает каждый следующий пуш полным прогоном.
- Не переписывать RULES.md под пилот. Этот документ — единственное описание пилота; итог пилота решает,
  что попадёт в RULES.md.
