# The grill outcome becomes one GitHub ticket, written by the CTO's own app

When the founders' answers land on the Artifact, the CTO catches them (lavish-axi poll) and
creates the full GitHub issue for the task in the product repo — once, after the grill, not
before. The issue is authored through the CTO's own GitHub App identity so it is visible who
wrote it. The card links to the issue; from there development is tracked in GitHub as today
(umbrella issues, PRs). Rejected: a draft ticket at spec time updated after the grill —
needless duplication.

Amended 2026-08-28 by [TICKETING.md](../TICKETING.md): the single ticket of this decision
is the umbrella; the `ticketed` stage adds one mandatory ticket per grill unit, bound to
the umbrella — the binding ADR-0006 already reads.
